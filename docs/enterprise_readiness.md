# Enterprise readiness map

What a security/platform reviewer asks for, where it lives, how it is tested, and what is **not** done.

| Requirement | Implementation | Tests | Honest gap |
|---|---|---|---|
| **Agent identity (IAM)** | `IdentityIssuer` (EdDSA, `kid`, rotation with overlap; ADR-0010) mints per-call JWTs: `sub=agent:<role>`, `sid=<session>`, `aud=<server>`, `scope`, `exp` (60 s), `jti`. MCP servers verify signature, audience, expiry, scope and reject `jti` replay with **public keys only** (JWKS; `/.well-known/jwks.json`), so they cannot mint. Client-supplied `_identity` is stripped; servers inject the verified one. HS256 remains only as an explicit dev fallback (`SA_IDENTITY_ALG=hs256`; refused when `SA_ENV=production`) | forged/tampered/`alg:none`/key-confusion/wrong-audience/expired/replay tokens; rotated key verifies in overlap, retired key rejected; server cannot mint; spoofed identity ignored; attribution across real stdio processes (`tests/test_security_v2.py`) | Needs the optional `[crypto]` extra (else dev HS256 with a warning). Private key not in a KMS/HSM; stdio servers get a JWKS snapshot; no workload-identity (SPIFFE/mTLS) binding. **Closed:** shared-secret mint-by-any-verifier |
| **Audit & attribution** | Hash-chained audit in the runtime DB (decisions, approvals, clarifications, handoffs, kill-switch hits, flag changes) and the business DB (refunds, cancellations, tickets) with agent + session on every row. `supportagent audit verify\|replay` | edit / delete / re-attribution detection; concurrent writers from 2 processes keep one chain; signed head anchors detect tail truncation, consistent rewrites and anchor-log edits (`tests/test_audit_anchors.py`) | Anchors only protect you once shipped to write-once storage (recipes in compliance.md) and the job is scheduled by you; the local anchor file and key share the attacker's host. **Closed in code:** tail truncation is detectable. **Open:** no automatic shipping, no SIEM log shipping |
| **PII masking** | `PIIVault`: ingress tokenization of user text and tool results (field-aware + regex), egress restore only for provably-own data, tool-arg restore for internal systems, cards/SSN hard-redacted. Eval metric **raw PII sent to LLM**: baseline 77% → final 0% | LLM-call recorder asserts no raw email/phone/address/card; foreign PII never restored; checkpoints stay tokenized | Regex/field-based detection (no NER) will miss free-form names/addresses in unstructured text. **Closed:** vault values and memory are AES-256-GCM at rest with per-customer keys when `SA_VAULT_KEY` is set (fail closed in production; `tests/test_privacy.py`). **Open:** plaintext in dev without a key; `Session.customer_email` and traces not sealed; master key from env, not KMS; no per-tenant scoping |
| **Injection mitigation** | Layered; see ADR-0004 | red-team scenarios, intent grounding | Fixed attacker suite; no adaptive red-teaming |
| **Approval gates** | Pause → persist → decide → resume exactly once; sync auto-reviewer for evals | crash/resume; deny path; kill switch beats approved action | Reviewer desk and admin API now require `SA_ADMIN_TOKEN` or an OIDC JWT (optional required role), CSRF-safe POSTs, reviewer attributed from auth, double-decision 409 (`tests/test_admin_auth.py`). **Open:** no 4-eyes, no per-action RBAC beyond one optional role, no SLA timers (ADR-0006) |
| **Clarification mechanics** | `ask_user` tool: `choice` / `confirm` / `free_text`, schema-validated, persisted in session, resumable after restart, 2 re-asks then safe degrade (never guesses a destructive target); answers pass the input guard; counts as customer intent | restart-resume, invalid answers, injection in answer, schema errors | No timeout/reminder for unanswered questions |
| **Kill switch / flags** | `kill_switch.global` (stops every turn, mid-session), `kill_switch.money` (blocks money/cancel tools even for already-approved actions; read-only help continues). CLI + admin API (bearer token, constant-time compare, disabled when unset) | mid-session flip, pending-approval flip, admin auth | Flags polled from SQLite per use; at scale use a flag service with push |
| **Safe prompt rollout** | Sticky deterministic canary arms; per-session prompt version + hash recorded in audit; **shadow mode** replays a candidate prompt in dry-run (writes simulated, no approvals/memory) *before* the live turn so both see the same data; `evals/promote.py` blocks promotion on any quality/safety/PII regression | canary proportionality/stickiness, shadow isolation (exactly one real refund), divergence recording, promotion gate | Shadow doubles latency in-process; production should run it async against a read replica |
| **Tool orchestration** | per-call timeouts, reconnect, circuit breaker, idempotency, rate limit, least-privilege allowlists | MCP tests | **Not built:** parallel tool calls, result caching, tool versioning |
| **Multi-agent** | triage → least-privilege specialists, guarded handoff | misroute recovery, handoff blocks | **Not built:** consensus (critic/verifier agent or two-model agreement before money moves) |
| **State & memory** | durable sessions, exactly-once resume, poisoning-resistant long-term memory | crash-resume, memory write policy; delete-on-request with crypto-shredding, transcript redaction and audit tombstone (`supportagent privacy delete`; ADR-0011) | **Closed:** delete-on-request preserving chain integrity. **Not built:** TTL/expiry, consent records, data-subject access/export; business records and the pseudonymous customer id on audit rows are retained by design |
| **Observability** | OTel-GenAI-style spans, cost accounting, dashboard, Prometheus counters incl. kill-switch gauges | tracing tests | **Not built:** structured logs, alert rules/SLOs |
| **Portability / sandbox** | `run_calculation` runs in an isolated child: POSIX rlimits (CPU 2 s, 256 MiB) as before; on Windows a Job Object (256 MiB, 2 s CPU, kill-on-close) assigned by the parent, plus the wall-clock timeout on both | `tests/test_portability.py` (memory limit enforced under a Job Object; rlimits read back on POSIX) | Windows limits are best effort (assigned right after process creation; Job CPU accounting is coarse, the wall-clock timeout is the effective bound). Arbitrary code still needs gVisor/Firecracker |
