supportagent demo - offline: simulated model, real harness, real HTTP API, fresh state

== 1. Refund within policy and under the $100 auto cap -> executed automatically
$ curl -s localhost:8080/api/chat -d '{"customer_id": "C001", "message": "Refund ORD-1001 please, I changed my mind"}'
HTTP 200 {
 "session_id": "S-1",
 "status": "done",
 "reply": "Your refund of $37.50 for order ORD-1001 has been issued. It should reach your original payment method in 5-10 business days."
}

== 2. High-value refund -> the run PAUSES for a human reviewer
$ curl -s localhost:8080/api/chat -d '{"customer_id": "C001", "message": "Refund ORD-1005 please, the espresso machine. Changed my mind."}'
HTTP 200 {
 "session_id": "S-2",
 "status": "awaiting_approval",
 "reply": "This action needs human approval; I'll update you once it's reviewed.",
 "approval_id": "APR-1"
}
$ curl -s localhost:8080/api/approvals -H 'Authorization: Bearer $REVIEWER' | jq '.pending'
HTTP 200 [
 {
  "id": "APR-1",
  "tool": "orders__issue_refund",
  "reason": "over_auto_cap",
  "status": "pending"
 }
]
$ curl -s -X POST localhost:8080/api/approvals/APR-1/decide -H 'Authorization: Bearer $REVIEWER' -d '{"approve": true}'
HTTP 200 {
 "approval": {
  "id": "APR-1",
  "status": "approved",
  "reviewer": "admin"
 },
 "status": "done",
 "reply": "Your refund of $250.00 for order ORD-1005 has been issued. It should reach your original payment method in 5-10 business days."
}
