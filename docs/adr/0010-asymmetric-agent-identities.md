# ADR-0010: Asymmetric agent identities (EdDSA + JWKS, rotation, verify-only servers)

**Status:** accepted. Closes the trade-off recorded in ADR-0007 (HS256 shared secret); ADR-0007's claims, TTL, audience binding and replay rules are unchanged.

**Context.** With HS256 every MCP server holds the same secret the harness signs with, so a compromised `tickets` server can mint a `refunds:issue` token for `orders`. The runtime is stdlib-only (ADR-0001), and Python has no stdlib asymmetric signatures.

**Decision.**
- Sign with **EdDSA (Ed25519)**; tokens carry a `kid`. The signing keys live in a `KeyRing` inside the issuing process only (`security/asymmetric.py`). MCP servers receive a `JwksVerifier` built from the **public** JWKS (`MCP_JWKS` inline for stdio children, `MCP_JWKS_FILE`/`MCP_JWKS_URL` for long-lived servers). The verifier has no `issue()` and no private material, so a server can verify but cannot mint. `GET /.well-known/jwks.json` on the API serves the same public set.
- **Rotation with overlap.** `rotate()` creates a new active key; the previous key becomes *retiring* and keeps verifying until `rotation_time + overlap` (default 120 s, at least 2x the 60 s token TTL) and is then dropped from the JWKS. The deadline is also published as `x-verify-until`, so a verifier holding a stale JWKS copy still refuses the retired key (`key retired`); a verifier with a fresh copy says `unknown kid`. An unknown `kid` triggers one JWKS re-fetch, so rotations propagate without a restart wherever the source is a file, URL or callable.
- **Unchanged guarantees:** audience binding, 60 s TTL, per-token `jti` replay rejection (`ReplayGuard`), server-side scope checks, `_identity` stripped from client args. New: a verifier refuses tokens whose `exp - iat` exceeds 300 s, and accepts only the algorithms it was configured with (EdDSA for agents), which rejects `alg:none` and HS256 "public key as HMAC secret" confusion before any signature check.
- **Optional dependency.** Needs the `[crypto]` extra (`cryptography`). `make_identity()` picks: `SA_IDENTITY_ALG=eddsa` (hard error with install hint if the package is missing), `hs256` (explicit dev opt-in), or `auto` (default: EdDSA when installed; an explicit `SA_JWT_SECRET` means HS256; otherwise a **loud warning** and a random HS256 secret in dev). With `SA_ENV=production`, HS256 and silent downgrade are refused.
- **Same machinery for people.** The admin API and reviewer desk accept either `SA_ADMIN_TOKEN` (constant-time compare) or an OIDC bearer JWT (RS256 or EdDSA) verified by `JwksVerifier` with issuer, audience, expiry and an optional required role (`security/adminauth.py`). Approval POSTs are CSRF-safe: bearer header (never a cookie), `Origin` must match `Host`, `application/json` required; the reviewer recorded is the authenticated principal, not a body field; a second decision returns 409.

**Consequences.** A stolen server cannot forge identities for any server; key compromise is limited to the harness, and rotation bounds the blast radius. Cost: one Ed25519 signature per call (microseconds) and an optional dependency.

**Not solved (see enterprise_readiness.md).** Private keys are in process memory or an optional 0600 file, not a KMS/HSM. Stdio children get a JWKS *snapshot* (rotation reaches them only through a file/URL JWKS or a restart). No workload-identity (SPIFFE/mTLS) binding of the caller; a stolen valid token is usable for up to 60 s, once, against its own audience. RS256 is verification-only (for external IdPs); issuing is EdDSA only.
