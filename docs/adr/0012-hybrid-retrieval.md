# ADR-0012: Hybrid retrieval (BM25 + dense, reciprocal rank fusion) as an opt-in extra

**Status:** accepted (BM25 remains the default; hybrid is opt-in)

**Context.** Policy retrieval was lexical BM25 only. Two documented misses (F6: "my package never arrived" vs *Lost Packages*, "customer has many refunds recently" vs *Refund Abuse Review*) showed that vocabulary mismatch is the failure mode, and a 12-question set cannot tell us whether a fix generalizes. The core is dependency-free (ADR-0001), the eval ladder must stay deterministic and offline, and ground truth for the refund/escalation/subscription scenarios depends on those policies' exact text.

**Decision.**
1. **Fusion.** Rank with BM25 (improved analyzer + query expansion) and a dense embedder separately, then fuse with reciprocal rank fusion, `score = sum_r w_r / (k + rank_r)`. RRF needs no score calibration between the two rankers. `rag/hybrid.py`.
2. **Pluggable dense backend** (`rag/embeddings.py`): (a) local `fastembed` or `sentence-transformers` model, optional extras; (b) hosted Voyage/OpenAI embeddings over plain HTTPS, constructed only when a key is present (Anthropic has no embeddings endpoint and points to Voyage); (c) a deterministic offline fallback, a character n-gram TF-IDF hashing embedder, so CI never needs a network or a model download. `SA_EMBEDDER=auto` takes the best installed local model and falls back to (c); an explicit but unavailable backend raises, and the factory degrades to BM25 with a warning.
3. **Hooks.** A query expansion/rewrite hook (`rag/expansion.py`: corpus-vocabulary spelling repair, a small support-domain thesaurus, an optional callable for an LLM rewriter that is never used by default) feeds only the lexical side. A rerank hook (`rag/rerank.py`: dependency-free heuristic, optional cross-encoder) reorders the fused pool.
4. **Default unchanged.** `SA_RETRIEVAL_MODE` defaults to `bm25`, which returns the original `PolicyIndex` with the original analyzer. The kb MCP server and therefore the policy specialist read this flag; the eval ladder's pass/fail results for the policy scenarios did not change. Growing the corpus did change which second passage the BM25 default cites for some queries.
5. **Abstention.** Hybrid exposes two evidence signals (idf-weighted BM25 term coverage, top dense cosine) and an optional `abstain=(t_cov, t_cos)` so "no answer" can be returned instead of the nearest wrong section. It is off by default; thresholds are tuned on the dev split.
6. **Evaluation is a study, not a demo.** ~170 labeled questions (paraphrase, typo, vocabulary mismatch, multi-section, no-answer) over an expanded 53-section corpus, a stratified dev/test split, and bootstrap CIs. Selectable knobs are tuned on dev only; test is read once. The report `docs/retrieval_results.md` is generated by `python -m evals.retrieval_eval --report` / `supportagent kb eval`; no number in it is typed by hand.

**Consequences.**
- (+) The default path and CI stay stdlib-only and deterministic; hybrid is one environment variable away, with a clean fallback.
- (+) The same code path is measured and shipped: the eval drives the same `HybridIndex` the MCP server uses.
- (-) Questions, gold labels, thesaurus and code were all written by the same LLM and none were human-reviewed; the thesaurus was written after the questions existed. The dev/test split controls numeric tuning leakage, not author leakage. See `evals/retrieval/PROVENANCE.md`.
- (-) The offline hashing embedder is lexical in disguise: it fixes typos and morphology, not synonymy. Only a real embedding model can claim semantic recall, and results depend on the model (see the generated report for what actually ran).
- (-) With ~85 test questions, and about a dozen unanswerable ones, confidence intervals are wide; small differences are not evidence.
- (-) Pure-Python dot products are fine for dozens of chunks; a real corpus needs an ANN index (see ADR-0006).

**Alternatives.** Dense only (loses exact-match behavior on numbers and identifiers, and is not robust to missing models); learned sparse (SPLADE) or ColBERT-style late interaction (better recall, heavy dependencies); LLM query rewriting by default (cost, non-determinism, and an injection surface); weighted score fusion (needs calibrated scores; RRF does not).
